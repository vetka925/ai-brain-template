# Reflect

The procedure for recording, authorship and review is in `wiki/meta/reflections.md`; do not duplicate it here.

1. Correct or complete the active work first, then record, unless the record would otherwise lose necessary facts.
2. Get the exact current model name from the session or live configuration before writing; if it is not exposed, write `unknown (exact model not recorded)`. A product label or family is not authorship.
3. Search `reflections.md` and its archive for the same failure. A repeat links to the earlier entry and says why the existing safeguard did not suffice.
4. Write one short entry: date, author model, what happened with an evidence link, why, the concrete change or check made, or «not verified».
5. Do not add a permanent rule. A proposed rule goes to `wiki/meta/rule-proposals.md` with exact text and evidence; the owner decides.
6. Finish through the root contract's write procedure (log entry, rotate, Git).

Reflection is useful as material for changing a procedure or adding a check. Keeping the journal by itself does not prevent repeats; a lesson that is not found before a similar task is lost. That is why entries stay short, searchable and linked to the fix.
